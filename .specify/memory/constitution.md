# StreamTube Constitution

## Core Principles

### I. Single Responsibility (NON-NEGOTIABLE)

Every module, service, and function MUST have a clear, focused responsibility scoped to its own domain. When a module starts owning logic or entities from another domain (e.g., a `VideosService` creating a `Channel` entity), it MUST be extracted immediately into the proper module — deferring the extraction is not permitted. Services MUST NOT create or own entities that belong to another module's domain.

### II. Type Safety (NON-NEGOTIABLE)

All layers MUST use strict TypeScript. The project MUST compile cleanly: `npx tsc --noEmit` MUST exit with code 0. TypeScript compilation errors MUST NOT be left as debt for future tasks — they must be fixed before the task is declared done.

### III. Test Pyramid (NON-NEGOTIABLE)

Every change MUST be tested at three levels:
- **Unit** (`*.spec.ts`) — isolated logic with mocked dependencies
- **Integration** (`*.integration-spec.ts`) — real database, real TypeORM
- **E2E** (`*.e2e-spec.ts`) — full HTTP stack via Supertest

The full test suite MUST pass before a task is declared done. During development, run only the tests related to the modified code; run the full suite before finishing.

### IV. Versioned Migrations (NON-NEGOTIABLE)

Schema changes MUST be applied via versioned TypeORM migrations generated by the TypeORM CLI. Auto-sync (`synchronize: true`) MUST NOT be used in any environment. After any entity change, `npm run migration:run` MUST be executed inside the container, and the generated migration file MUST be committed.

### V. Definition of Done Gate (NON-NEGOTIABLE)

A task is only complete when ALL five criteria pass:

1. The relevant test suite passes (unit + integration + e2e affected by the change)
2. The full test suite passes
3. `npm run migration:run` was executed after any entity change (backend only)
4. `npx tsc --noEmit` exits with code 0
5. `npm run lint` passes

If any of these fails, the task is NOT done.

### VI. Docker Networking

Service connections MUST use Docker Compose service names as hostnames (e.g., `db`, `redis`, `minio`). The values `localhost` and `127.0.0.1` MUST NOT appear in environment variables, configuration files, or code that references inter-service connections. This applies to all services: database, cache, queue, storage, and email.

### VII. Scope Discipline

Each PR or task MUST address exactly one feature, fix, or refactoring. Cosmetic changes (formatting, renaming) MUST NOT be mixed with functional changes. Out-of-scope findings MUST be logged as separate tasks instead of being acted upon in the current scope.

## Additional Constraints

### Code Quality

- ESLint and Prettier MUST be configured and enforced; `npm run lint` MUST pass before merge
- Code reviews SHOULD focus on readability, maintainability, and adherence to the principles above

### Git Conventions

- Commits MUST NOT go directly to `main`
- Branch names MUST follow: `feature/*`, `bugfix/*`, `hotfix/*`, `docs/*`
- The Git Flow workflow MUST be followed: branches start from `dev` and merge back into `dev`; `dev` is merged into `main` only when stable
- Commit messages SHOULD be short and focused on the "why" of the change, not the "what"

### Architecture Boundaries

- The Frontend (Next.js) MUST communicate with the Backend only via the REST API — no direct database or storage access
- The API MUST NOT serve binary video content directly during upload; uploads MUST use pre-signed URLs to the object storage
- The Video Worker MUST run as a separate process and container from the API; CPU-intensive processing MUST NOT occur in the API process
- All infrastructure (storage, queue, worker) MUST be provisioned via Docker Compose and start with a single command — no manual provisioning steps are permitted

## Quality Gates

### Pre-Implementation

- `spec.md`, `plan.md`, and `tasks.md` MUST exist and be cross-consistent before implementation begins
- Constitution compliance MUST be checked by `/speckit-analyze` — violations are CRITICAL

### Pre-Merge

- All five Definition of Done criteria MUST pass (Principle V)
- No open TypeScript errors (Principle II)
- No lint violations (Principle II + Additional Constraints)
- Test pyramid coverage present for all changed modules (Principle III)

---

## Governance

This constitution supersedes all other project practices and conventions. In cases of conflict between convenience, speed, or historical patterns and a principle stated here, the constitution takes precedence.

Amendments require an explicit update to this file with a documented rationale. The constitution MUST NOT be silently ignored — if a principle needs to change, update it here first.
